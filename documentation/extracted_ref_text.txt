SYNOPSIS 
The Bus Booking System is a web -based application developed to simplify the process of searching intercity buses, selecting 
preferred seats, and managing passenger bookings. The system provides users with an intuitive and responsive platform to  plan 
their journey, inspect seating arrangements, and secure confirmed travel tickets. 
Module 3: Seat Booking & Passenger Management is  responsible for the core booking workflow. It provides interactive seat 
layouts for diverse bus categories including Seater, Sleeper, and Semi -Sleeper. Users can inspect seat availability in real time, 
choose vacant berths or chairs across lower and upper  decks, and provide comprehensive passenger information including 
boarding and dropping landmarks. 
The module uses React.js with Vite for the frontend user interface and Node.js with Express.js for the backend API. MongoDB i s 
used as the database for storing bus inventories, individual seat states, and booking records. REST APIs facilitate seamless 
communication between the frontend interface and backend controllers. 
Safety and validation mechanisms are rigorously enforced. A dedicated ladies -reserved seat algorithm detects adjacent female 
passengers and restricts adjacent booking access strictly to female travelers. Mandatory passenger validations ensure name, age, 
email format, and 10-digit mobile number accuracy before confirming ticket orders. 
OBJECTIVE 
• Display bus search results with operator schedules, category details, and base pricing. 
• Render interactive, deck-specific seat maps for Seater, Sleeper, and Semi-Sleeper layouts. 
• Allow users to select available seats with visual color-coded availability indicators. 
• Enforce adjacent ladies safety rules to prevent unauthorized seat allocation. 
• Collect and validate passenger credentials including Name, Age, Gender, Email, and Mobile. 
• Facilitate pickup and drop-off point selection with scheduled timings and landmark details. 
• Calculate dynamic fares incorporating optional meal add-ons and mandatory 5% GST tax. 
• Persist confirmed booking transactions and atomically update seat inventory in MongoDB. 
 
SCOPE 
• Interactive seat layout visualization across single, double, lower, and upper deck configurations. 
• Client-side and server-side validation for passenger details and contact verification. 
• Automated gender reservation policy for seats adjacent to booked female travelers. 
• Dynamic fare computation engine calculating seat fares, meal charges, and GST amounts. 
• REST API endpoints for seat retrieval, booking creation, and availability synchronization. 
• Atomic database state transitions transitioning seats from available to booked.

PROJECT DESCRIPTION 
The Bus Booking System is a full -stack web application consisting of a React.js (Vite) frontend, Node.js/Express.js backend, and 
MongoDB database. Module 3 delivers the complete seat sel ection and passenger management lifecycle, connecting search 
results with verified booking records. 
The frontend provides an interactive seat selection interface with visual deck switchers, passenger data forms, and booking 
confirmation screens. The backen d handles REST API routing, request validation, ladies seat safety checks, fare calculation, and 
atomic database persistence within MongoDB. 
 
Technology Purpose 
React.js Frontend user interface, component hierarchy, and dynamic state management 
Vite Fast frontend build tooling and local development server environment 
Node.js Asynchronous JavaScript runtime executing the backend server 
Express.js REST API development, request routing, and booking middleware 
MongoDB NoSQL document database for buses, seat inventories, and booking records 
Mongoose Object Data Modeling (ODM) library defining schemas and validation logic 
Axios / HTTP Asynchronous API communication between React frontend and Express backend 
DB DESIGN 
Database Design describes how data is organized and stored in MongoDB. Module 3 primarily interacts with the 'buses', 'seats', 
and 'bookings' collections. The primary Booking schema structure is detailed below: 
 
Field Data Type Description 
_id ObjectId Unique booking identifier generated by MongoDB 
busId ObjectId Reference foreign key linking to the Bus document 
seats Array (String) Array of reserved seat identifiers (e.g., ['DL1', 'DL2', 'S1A']) 
passengers Array (Object) Embedded passenger subdocuments (Name, Age, Gender, Contact) 
seatFare Number Calculated base fare across all selected seats 
totalAmount Number Final grand total payable including optional meals and 5% GST 
status String Booking status lifecycle ('confirmed' or 'cancelled') 
Database flow: React Frontend → Booking API (POST /api/bookings) → Node.js/Express → Mongoose → MongoDB → Seats & 
Bookings Collections. 
Data persistence guarantees atomicity: upon booking confirmation, selected seats are marked as 'booked' via 
Seat.updateMany(), available seat tallies are decremented in the Bus document, and a verified Booking record is stored.
